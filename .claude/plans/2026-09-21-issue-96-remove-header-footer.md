# Remove the Header and Footer organisms

## Goal

Delete `mud-header` (with its four sub-components) and `mud-footer` from the library, Storybook,
the web-components demo and every doc or script that names them, so nothing in the repo still
refers to either organism.

## Problem

The Header and Footer organisms are no longer wanted in the design system, yet they still ship as
six custom elements, carry their own tokens, and appear in Storybook, the web-components demo and
the `mud-design` skill that tells consuming projects which component to use.

## Acceptance bar

- `git grep -nE "mud-header|mud-footer|MudHeader|MudFooter" -- ':!.claude/plans' ':!CHANGELOG.md'`
  prints nothing, and neither does `git ls-files | grep -iE "(mud|cor)-(header|footer)"`, which
  also catches files under the organisms' pre-rename `cor-` names.
- The built Storybook index has no `Organisms/Header` or `Organisms/Footer` entry.
- `yarn lint`, `yarn typecheck`, `yarn test`, `yarn test:scripts`, `yarn docs:check`, `yarn build`,
  `yarn sp.build`, `yarn test.storybook`, `yarn build.web` and `yarn validate.package` pass.
- `CHANGELOG.md` names every removed element, token group and export, with a migration note.

## Spec/issue link

<https://github.com/egov-moldova/design-system/issues/96> — "To delete Header and Footer
organisms from Storybook, and clean up codebase and examples".

## Options

| Option | Cost |
| --- | --- |
| A. Delete the components, tokens, exports, stories and examples | Breaking: six custom elements shipped in `@egov-moldova/mud@1.1.9` disappear |
| B. Delete only the stories and demo examples | Non-breaking, but the components stay published with no docs page |
| C. B now, `@deprecated` on the components, delete in a later major | Two PRs; consumers get one release of warning |

## Decision

A — confirmed by the issue owner on 2026-09-21. The issue asks for the codebase to be cleaned up,
not only Storybook. It ships as a breaking change with a `Removed` CHANGELOG entry.

## Global constraints

- Branch `fix/issue-96-remove-header-footer`, based on `upstream/main` at `0ceb147` (PR #80 and
  PR #81 are already merged into it).
- Generated files (`src/components.d.ts`, component `readme.md`) are regenerated by `yarn build`,
  never hand-edited, and committed with the change that regenerates them.
- Paths are staged explicitly.
- Historical plans in `.claude/plans/` keep their mentions: they record past work.
