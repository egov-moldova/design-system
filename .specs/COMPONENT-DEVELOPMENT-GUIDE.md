# Component Development Guide — `@egovmd/mud`

## 1. Purpose

This guide describes how to build a Stencil web component in `@egovmd/mud`: file anatomy, member order, CSS architecture patterns, slot validation, stories, tests, and the pixel-perfect QA loop.

For runtime guidance (anti-patterns, full command reference, decision matrices), see [`src/components/AGENTS.md`](../src/components/AGENTS.md) and its `_agents/*.md` subfiles. For the workflow itself, use the `new-component` or `custom-component` subagents.

## 2. Component Anatomy

Every component lives in its own folder under `src/components/`:

```text
src/components/mud-<name>/
├── mud-<name>.tsx              # REQUIRED — Stencil class component
├── mud-<name>.css              # REQUIRED — styles (Shadow DOM)
├── mud-<name>.stories.ts       # REQUIRED — Storybook CSF3 stories
├── mud-<name>.types.ts         # OPTIONAL — exported TypeScript interfaces
├── mud-<name>.enums.ts         # OPTIONAL — variant / size enums
├── mud-<name>.constants.ts     # OPTIONAL — internal constants
├── readme.md                   # AUTO-generated by Stencil — do not edit
└── test/
    └── mud-<name>.spec.tsx     # REQUIRED — unit tests
```

Components are kept under `src/hidden/` while WIP. Run the `/migrate-component` slash command to graduate them to `src/components/` once they pass audit.

## 3. TSX Member Order

The class body must follow this order exactly. Auditors enforce it.

1. `@Prop({ reflect: true })` — public props (with JSDoc, defaults, enum types from `.enums.ts`)
2. `@State()` — internal reactive state
3. `@Element()` — host element reference (`@Element() host!: HTMLElement`)
4. `@AttachInternals()` — form internals (form elements only; `@AttachInternals() internals!: ElementInternals`)
5. `@Event()` — custom events with `cor` prefix (`@Event() corChange!: EventEmitter<T>`)
6. `@Watch()` — prop watchers (rule below)
7. `@Listen()` — DOM event listeners
8. Lifecycle hooks — `componentWillLoad` → `componentDidLoad` → `componentDidUpdate`
9. Private methods and refs
10. `render()` — always last

**`@Watch()` rule**: forbidden for triggering side effects or state cascades (use `@Listen()` instead). Allowed only for syncing native DOM properties that cannot be reflected via attributes (e.g., `inputElement.indeterminate`, `inputElement.checked`).

## 4. TypeScript Strict Mode

All decorator properties use definite-assignment `!`:

```typescript
@Element() host!: HTMLElement;
@Event() corChange!: EventEmitter<boolean>;
@AttachInternals() internals!: ElementInternals;
```

Object maps use explicit `Record<>`:

```typescript
const sizeMap: Record<string, number> = { sm: 12, md: 16, lg: 20 };
```

Optional chaining uses nullish coalescing:

```typescript
const tag = this.host.firstElementChild?.tagName?.toLowerCase() ?? '';
```

No implicit `any`. Optional props use `?`:

```typescript
@Prop() width?: string | number;
```

Story render functions are typed:

```typescript
type ButtonArgs = { variant: string; size: string };
const renderButton = (args: ButtonArgs) => /*html*/ `<mud-button variant="${args.variant}" size="${args.size}">Click</mud-button>`;
```

See [`_agents/typescript-strict.md`](../_agents/typescript-strict.md) for the complete rule set.

## 5. CSS Architecture — Two Patterns

Components fall into one of two CSS patterns. Pick one — never mix.

### Pattern A: Slotted (mud-button style)

Used for components that wrap user-provided elements (buttons, links, anchors).

- Style slot content via `::slotted(*)` selectors
- Variant via attribute selectors: `:host([variant='primary'])`
- Size via attribute selectors: `:host([size='md'])`
- Pseudo-states on slotted: `::slotted(*:hover:not(:disabled))`
- Disabled via `::slotted(button:disabled)`, `::slotted(a[aria-disabled='true'])`, `::slotted(input:disabled)`

Example:

```css
:host {
  display: inline-block;
}

:host([variant='primary']) ::slotted(*) {
  background: var(--button-primary-background-default);
  color: var(--button-primary-text-default);
}

:host([variant='primary']) ::slotted(*:hover:not(:disabled)) {
  background: var(--button-primary-background-hover);
}
```

### Pattern B: Internal DOM (mud-input style)

Used for components that render their own internal markup (inputs, dropdowns, panels).

- `:host` CSS variables drive size mapping
- Internal elements consume host-level vars: `.container { min-height: var(--input-height); }`
- Size overrides reassign host vars: `:host([size='md']) { --input-height: var(--input-md-height); }`
- State via host class: `:host(.is-focused) .container { ... }`

Example:

```css
:host {
  --input-height: var(--input-md-height);
  display: block;
}

:host([size='sm']) { --input-height: var(--input-sm-height); }
:host([size='lg']) { --input-height: var(--input-lg-height); }

.container {
  min-height: var(--input-height);
  background: var(--input-background-default);
}

:host(.is-focused) .container {
  border-color: var(--input-border-color-focus);
}
```

See [`src/components/_agents/css-architecture.md`](../src/components/_agents/css-architecture.md) and [`_agents/shadow-dom-patterns.md`](../_agents/shadow-dom-patterns.md) for the full pattern reference and shadow-DOM dual-selector rule.

## 6. Slot Validation Guards

Components with restricted slots (icon slots, helper text slots, etc.) use `invalidSlottedTag()`:

```tsx
import { invalidSlottedTag } from '../../utils/invalid-slotted-tag';

render() {
  if (invalidSlottedTag(this.host, 'icon-left', ['mud-icon'])) {
    return null;
  }
  return (
    <Host>
      <slot name="icon-left" />
      <slot />
    </Host>
  );
}
```

Common restrictions:

- Icon slots accept only `mud-icon`
- Helper-text slots accept only inline elements (`span`, `small`, `div`, `p`)
- Default slots without restrictions skip validation

See [`src/components/_agents/slot-patterns.md`](../src/components/_agents/slot-patterns.md) for the complete catalog.

## 7. Token-First Change Order

Whenever a component is modified, follow this dependency order:

1. **Tokens JSON** → update / add in `tokens/core/components/<name>.tokens.json`
2. **Build tokens** → `yarn tokens.build` (~5s)
3. **CSS** → update `mud-<name>.css` using `var(--token-name)` — wait for Stencil watch (~2–5s) or run `yarn dx:stencil:once`
4. **TSX** → update props, state, render logic — wait for Stencil watch (~2–5s)
5. **Stories** → update `.stories.ts` to cover new variants/states — Storybook HMR (~1s)

**Do NOT run `yarn build` during iteration.** Full build is only for final verification (Step 12 below).

See [`TOKEN-ARCHITECTURE.md`](TOKEN-ARCHITECTURE.md) for token naming and JSON structure.

## 8. Form-Associated Components

Form elements (input, select, textarea, checkbox, radio, toggle) MUST implement Stencil's form-associated API. Failure here is a Critical audit finding.

Requirements:

- `formAssociated: true` in `@Component` decorator
- `@AttachInternals() internals!: ElementInternals` property
- `internals.setFormValue(value)` in input/change handlers
- `formResetCallback()` — resets value and form state
- `formDisabledCallback(disabled: boolean)` — syncs `disabled` prop
- `formStateRestoreCallback(state, mode)` — handles browser auto-fill
- `updateValidity()` — copies all `ValidityState` flags to `internals.setValidity()`

See [`src/components/_agents/form-associated.md`](../src/components/_agents/form-associated.md) for the complete API and patterns, plus the canonical `mud-input` and `mud-checkbox` examples.

## 9. Storybook Stories (CSF3)

Required stories:

- `Default` — basic usage with default props
- `AllVariants` — grid showing every variant
- `AllSizes` — grid showing every size (if size prop exists)
- `States` — default, hover, focus, disabled
- Slot variations — with / without content, named slots
- Edge cases — long text, empty content, icon-only (if applicable)

Format rules:

- Import from `@storybook/web-components-vite` (NOT React)
- `component: 'mud-<name>'` — string tag name, NOT JS reference
- `render` function with HTML template strings, `/*html*/` prefix for IDE highlighting
- `title` follows atomic hierarchy: `Atoms/CorName`, `Molecules/CorName`, `Organisms/CorName`
- All render functions typed (`(args: ComponentArgs) =>`); bare `args =>` forbidden

See [`src/components/_agents/storybook-stories.md`](../src/components/_agents/storybook-stories.md) for full templates.

## 10. Unit Tests

Minimum coverage:

- Renders without errors (smoke test)
- All props apply (correct attributes reflected to host)
- All events fire with correct payload
- Internal state transitions
- Slot content renders correctly
- Disabled state blocks interaction
- ARIA attributes present in rendered DOM

Test file: `test/mud-<name>.spec.tsx`. Run with `yarn test`.

## 11. Pixel-Perfect QA Loop

Every component undergoes pixel-perfect comparison vs the Figma reference.

```text
mcp__playwright__browser_navigate({ url: "http://localhost:6007/iframe.html?id=atoms-mud-<name>--default" })
mcp__playwright__browser_wait_for({ time: 2 })
mcp__playwright__browser_console_messages({ level: "error" })   // fix errors BEFORE screenshotting
mcp__playwright__browser_take_screenshot({ type: "png", filename: ".playwright-mcp/current.png" })
mcp__image-compare__compare_images({
  image1_path: ".playwright-mcp/figma-ref.png",
  image2_path: ".playwright-mcp/current.png",
  diff_output_path: ".playwright-mcp/diff.png",
  threshold: 0.1
})
```

Threshold targets:

- **PASS**: < 0.5% pixel difference
- **WARNING**: 0.5–2% (review and decide)
- **FAIL**: > 2%

Test ALL states (default, hover, focus, active, disabled). Repeat until identical. Use the targeted rebuild matrix from §7 — do not full-build during iteration.

See [`_agents/pixel-perfect-qa.md`](../_agents/pixel-perfect-qa.md) for the full 8-step loop and best practices.

## 12. Accessibility (WCAG 2.1 AA)

- All interactive elements reachable via keyboard (Tab order follows reading order)
- `:focus-visible` styles defined; focus ring has ≥ 3:1 contrast
- Enter/Space activates interactive elements
- Escape closes overlays/dropdowns
- No keyboard traps
- ARIA labels present where visible text is absent
- `aria-disabled`, `aria-invalid`, `aria-required`, `aria-expanded`, `aria-selected` set per state
- Color contrast: 4.5:1 text, 3:1 large text and UI components
- No information conveyed by color alone
- `prefers-reduced-motion` honored for animations

Run `/audit-accessibility` for deep WCAG testing.

## 13. Final Verification

Before claiming complete:

1. `yarn lint` — zero errors
2. `yarn test` — all pass
3. `yarn build` — full production build clean
4. `yarn sp.build` — Storybook static export succeeds
5. `yarn tokens.audit` — zero missing token references
6. `mcp__playwright__browser_console_messages({ level: "error" })` — zero runtime errors
7. Pixel-perfect diff vs Figma — under 0.5%
8. Invoke `verification-before-completion` skill — confirms commands ran AND output was read

Pre-PR: run [`/pre-pr-check`](../.claude/commands/pre-pr-check.md). Pre-merge: run [`audit-production`](../.claude/agents/audit-production.md) subagent.

## 14. Common Anti-Patterns

Forbidden — auditors flag these as Critical:

1. Inline styles in TSX (`style="..."` in render) — violates CSP
2. Hardcoded values in CSS — every visual value must be a `var(--token)` reference
3. Direct `var(--palette-*)` reference in component CSS — use `--color-*` semantic equivalent
4. `any` types — use proper TypeScript types
5. `@ts-ignore` / `@ts-expect-error` without comment justifying it
6. Direct DOM manipulation outside lifecycle hooks
7. `this.host.classList.add/remove()` in handlers — use declarative `getHostClasses()` instead
8. CSS `transition: all` — specify exact properties
9. `!important` without comment justifying it
10. `@Watch()` for side effects — use `@Listen()` instead
11. Boolean props to control slot visibility — use CSS `:empty` or slot detection
12. Missing `invalidSlottedTag()` validation on restricted slots
13. `"components"` wrapper in token JSON — breaks all CSS variables

See [`_agents/anti-patterns.md`](../_agents/anti-patterns.md) for the complete catalog.
