## Step 3: Structural Audit

Evaluate the component against file structure and member order rules.

**File structure checklist:**

- [ ] All required files exist: `.tsx`, `.css`, `.stories.ts`
- [ ] Optional files follow naming: `.types.ts`, `.enums.ts`, `.constants.ts`
- [ ] Test file exists: `test/cor-{name}.spec.tsx`
- [ ] `readme.md` present (auto-generated by Stencil — do NOT modify)
- [ ] No extra/unexpected files in the component directory

**TSX member order (must match exactly):**

1. `@Prop({ reflect: true })` — with JSDoc, defaults, enum types
2. `@State()` — internal reactive state
3. `@Element()` — host element ref
4. `@AttachInternals()` — form internals (form elements only)
5. `@Event()` — custom events with `cor` prefix
6. `@Watch()` — prop watchers (if any; see rule below)
7. `@Listen()` — DOM event listeners
8. Lifecycle: `componentWillLoad` → `componentDidLoad` → `componentDidUpdate`
9. Private methods and private refs
10. `render()` — always last

**`@Watch()` rule**: Forbidden for triggering side effects or state cascades (use `@Listen()` instead). Allowed only for syncing native DOM properties that cannot be reflected via attributes (e.g., `inputElement.indeterminate = newValue`, `inputElement.checked = newValue`).

Report any ordering violations.

## Step 3.5: TypeScript Strict Mode Audit

**Check for TypeScript strict mode violations (CRITICAL):**

- [ ] All `@Element()` properties have `!` assertion: `@Element() host!: HTMLElement;`
- [ ] All `@Event()` properties have `!` assertion: `@Event() corChange!: EventEmitter<T>;`
- [ ] All `@AttachInternals()` properties have `!` assertion: `@AttachInternals() internals!: ElementInternals;`
- [ ] Object maps have explicit `Record<string, T>` type annotations
- [ ] Optional chaining uses nullish coalescing: `this.host.firstElementChild?.tagName?.toLowerCase() ?? ''`
- [ ] Story render functions have typed args (`(args: ComponentArgs)` preferred; `(args: any)` allowed)
- [ ] No implicit `any` types
- [ ] Optional props use `?` syntax: `@Prop() width?: string | number;`

**Common violations to check:**

```typescript
// ❌ WRONG
@Element() host: HTMLElement;
@Event() corChange: EventEmitter<boolean>;
const sizeMap = { sm: 12, md: 16 };
const tag = this.host.firstElementChild?.tagName?.toLowerCase();
const renderComponent = args => { ... };

// ✅ CORRECT
@Element() host!: HTMLElement;
@Event() corChange!: EventEmitter<boolean>;
const sizeMap: Record<string, number> = { sm: 12, md: 16 };
const tag = this.host.firstElementChild?.tagName?.toLowerCase() ?? '';
const renderComponent = (args: ComponentArgs) => { ... };
```

Verify no TypeScript errors:

```bash
yarn build
```

## Step 4: Token Compliance Audit

**Check for hardcoded values (CRITICAL — Anti-Pattern #1):**

Search the `.css` file for:

- Raw hex colors (`#[0-9a-fA-F]{3,8}`)
- Raw pixel values for spacing/sizing (not `0px` or `1px` borders)
- Raw `rgb()`/`rgba()`/`hsl()` values
- Any value that should be a `var(--token-name)`

**Check for palette token usage (CRITICAL — Anti-Patterns #23 & #24):**

```bash
# Windows (PowerShell)
Select-String "palette-" src/components/cor-{name}/cor-{name}.css

# macOS / Linux (Unix)
grep "palette-" src/components/cor-{name}/cor-{name}.css
```

- Any match is a violation. Replace using the mapping table in `tokens/AGENTS.md` (see semantic token hierarchy).

**Check token references:**

- [ ] All CSS custom properties follow naming: `--{component}-{element}-{property}-{scale/state}` — scale/state MUST be last
- [ ] Component token file exists in `tokens/core/components/{name}.tokens.json`
- [ ] Token JSON uses `{token.path}` references — no raw hex/px in component tokens
- [ ] Every `var(--token)` used in CSS has a matching entry in built `dist/design-system/tokens/*.css`
- [ ] Base properties use fallback: `var(--button-font-family, var(--font-family-sans))`
- [ ] Variant-specific properties have NO hardcoded fallbacks
- [ ] No `var(--palette-*)` used directly in component CSS
- [ ] No `var(--palette-*)` used as fallback: `var(--component-token, var(--palette-*))` is forbidden
- [ ] All color fallbacks use `--color-*` semantic tokens (e.g., `var(--label-color, var(--color-neutral-text-weak))`)

Verify token build output:

// turbo

```bash
# Windows (PowerShell)
Get-ChildItem dist/design-system/tokens/*.css -ErrorAction SilentlyContinue

# macOS / Linux (Unix)
ls dist/design-system/tokens/*.css
```

Search for the component's tokens in built CSS:

```bash
# Windows (PowerShell)
Select-String -Path "dist/design-system/tokens/core.tokens.css" -Pattern "--{name}-" | Select-Object -First 20

# macOS / Linux (Unix)
grep "--{name}-" dist/design-system/tokens/core.tokens.css | head -n 20
```

## Step 5: CSS Architecture Audit

Determine which CSS pattern the component uses and verify correctness:

**Pattern A (Slotted — cor-button style):**

- [ ] Uses `::slotted(*)` for styling slot children
- [ ] Uses `:host([variant='x'])` for variant selectors (NOT class-based)
- [ ] Uses `:host([size='y'])` for size selectors
- [ ] Pseudo-states on slotted: `::slotted(*:hover:not(:disabled))`
- [ ] Disabled via `::slotted(button:disabled)`, `::slotted(a[aria-disabled='true'])`, `::slotted(input:disabled)`

**Pattern B (Internal DOM — cor-input style):**

- [ ] Uses `:host` CSS variables for size mapping
- [ ] Internal elements use host-level vars: `.container { min-height: var(--input-height); }`
- [ ] Size overrides reassign host vars: `:host([size='md']) { --input-height: var(--input-md-height); }`
- [ ] State via host class: `:host(.is-focused) .container { ... }`

**Common CSS issues:**

- [ ] No inline styles in TSX (Anti-Pattern #2)
- [ ] `:host { display: ... }` is set
- [ ] Transitions use `property 150ms ease-in-out` consistently (not 250ms, not `all`)
- [ ] PostCSS nesting uses `&` correctly
- [ ] No `!important` unless absolutely justified
- [ ] No `*` universal selectors outside `::slotted(*)`
- [ ] Disabled state sets `pointer-events: none` and `cursor: not-allowed`

## Step 6: TypeScript & Stencil Audit

**Decorators:**

- [ ] All visual props use `@Prop({ reflect: true })` — variant, size, disabled, etc.
- [ ] Props have JSDoc documentation
- [ ] Props have default values where appropriate
- [ ] Props use enum types from `.enums.ts` (not string literals)
- [ ] Events use `cor` prefix: `@Event() corButtonClick`
- [ ] Event payloads are typed: `EventEmitter<T>` (not bare `EventEmitter`)

**TypeScript quality:**

- [ ] No `any` types (Anti-Pattern #4)
- [ ] Public API props/methods have interfaces in `.types.ts`
- [ ] No unused imports or dead code
- [ ] No `@ts-ignore` or `@ts-expect-error` without justification
- [ ] Lifecycle hooks used correctly: `componentWillLoad` for data, `componentDidLoad` for DOM
- [ ] No direct DOM manipulation outside lifecycle hooks (Anti-Pattern #3)
- [ ] `@Watch()` only used for syncing native DOM properties (e.g., `inputElement.indeterminate`), NOT for side effects or state cascades — use `@Listen()` for side effects

**Host class management (Anti-Pattern #26):**

- [ ] No `this.host.classList.add/remove()` in `@Listen()` handlers or lifecycle methods
- [ ] Interactive components use declarative `getHostClasses()` pattern
- [ ] State tracked as private properties (`hovered`, `focused`, `pressed`)
- [ ] `<Host class={this.getHostClasses()}>` in render method
- [ ] See `src/components/_agents/component-structure.md` → Host Class Management

**Slot validation guards:**

- [ ] All named slots have validation guards at start of `render()` method
- [ ] Uses `invalidSlottedTag()` utility from `src/utils/invalid-slotted-tag`
- [ ] Validation checks element tagName before rendering
- [ ] Error messages clearly state valid element types
- [ ] Icon slots only accept `cor-icon` elements
- [ ] Helper text slots only accept inline elements (`span`, `small`, `div`, `p`)
- [ ] Slot names follow convention: `<slot />` for default, `<slot name="icon" />` for named
- [ ] Default slots without restrictions don't need validation

**Stencil Best Practices Compliance (CRITICAL for form elements):**

Identify component type and verify Stencil API compliance:

**For form elements (input, select, textarea, checkbox, radio, toggle):**

- [ ] `formAssociated: true` in `@Component` decorator
- [ ] `@AttachInternals() internals: ElementInternals` property declared
- [ ] `internals.setFormValue()` called in input/change handlers
- [ ] `formResetCallback()` implemented — resets value and form state
- [ ] `formDisabledCallback(disabled: boolean)` implemented — syncs disabled prop
- [ ] `formStateRestoreCallback(state, mode)` implemented — handles browser auto-fill
- [ ] `updateValidity()` method exists — syncs HTML5 validation with form
- [ ] All ValidityState flags properly copied to `internals.setValidity()`

**For interactive components (button, tabs, dropdown, modal):**

- [ ] Events follow Stencil naming: `@Event() corComponentAction`
- [ ] Event emitters properly typed: `EventEmitter<PayloadType>`
- [ ] Lifecycle callbacks used appropriately (not mixing concerns)

**If any form element checklist item fails → CRITICAL issue in audit report.**

## Step 7: Accessibility Audit

Navigate to the component story in Storybook and run accessibility checks:

```text
browser_navigate({ url: "http://localhost:6007/iframe.html?id=..." })
browser_wait_for({ time: 2 })
browser_snapshot()
```

**ARIA & Semantics:**

- [ ] Interactive elements have appropriate ARIA roles
- [ ] ARIA labels present where visible text is absent
- [ ] `aria-disabled="true"` on non-button disabled elements (e.g., `<a>`)
- [ ] No redundant ARIA (e.g., `role="button"` on `<button>`)
- [ ] Error states have `aria-invalid="true"` and `aria-describedby`

**Keyboard navigation:**

- [ ] Focusable via Tab: `browser_press_key({ key: "Tab" })`
- [ ] Focus ring visible: `:focus-visible` styles in CSS
- [ ] Enter/Space activates interactive elements
- [ ] Escape closes overlays/dropdowns (if applicable)
- [ ] No keyboard traps

**Visual accessibility:**

- [ ] Color contrast meets WCAG AA (4.5:1 text, 3:1 large text)
- [ ] Disabled state is distinguishable (opacity/color, not just cursor)
- [ ] Focus ring has sufficient contrast
- [ ] No information conveyed by color alone

Check for a11y warnings:

```text
browser_console_messages({ level: "warning" })
```

## Step 8: Security Audit

- [ ] **No inline styles** in TSX — violates CSP (`style="..."` in render)
- [ ] **No `innerHTML`** or `dangerouslySetInnerHTML` equivalents
- [ ] **No `eval()`** or `Function()` constructors
- [ ] **No external URL loading** without sanitization
- [ ] **Slot content validated** — `invalidSlottedTag()` used where restrictions apply
- [ ] **No sensitive data** in props or events (tokens, passwords, PII)
- [ ] **No `document.cookie`** or `localStorage` access in component code
- [ ] **Event payloads** don't leak internal state beyond what's needed

## Step 9: Performance Audit

- [ ] **No unnecessary re-renders** — `@State()` only for values that affect render
- [ ] **No heavy computation** in `render()` — move to lifecycle or private methods
- [ ] **Shadow DOM encapsulation** — `shadow: true` in component decorator
- [ ] **Lazy loading** — component uses standard Stencil lazy loading
- [ ] **No DOM queries in loops** — `querySelector` called once, cached
- [ ] **Event listeners cleaned up** — `@Listen` on `window`/`document` properly scoped
- [ ] **CSS `transition: all`** not used — specify exact properties
- [ ] **No large inline SVGs** — use `cor-icon` or external assets
- [ ] **Bundle impact** — no large external dependencies imported into component
