Integration guide — outside a bundler

Drop AGE components into anything that emits HTML: a static page, a server-rendered template (PHP, Razor, Twig, Blade), or a desktop WebView. Every mud-* is a W3C Custom Element, so the integration story is the same everywhere a browser renders HTML — only the delivery of asset files changes.

1. What the build emits #

TL;DR Ship the entire dist/design-system/ folder. The lazy loader resolves chunks and SVG assets via import.meta.url — split it and asset resolution breaks at runtime.

After yarn build, the relevant artifacts live in dist/design-system/:

File / folder Purpose Required?
design-system.esm.js Lazy-loader entry. Discovers and import()s component chunks on demand. Yes
design-system.css Global base styles (reset, body defaults, focus ring helpers). Yes
tokens/core.tokens.css Light-theme CSS variables (palette + semantic). Yes
tokens/core.dark.tokens.css Dark-theme overrides, scoped under [data-theme='dark']. Recommended
p-*.js chunks One per component, lazy-loaded by the entry. Auto-served
assets/ SVG sprites (used by mud-icon, mud-logo, …). Yes — keep alongside the entry

2. Three-line integration #

TL;DR Two stylesheets and one ES module. That is the entire contract.

Anywhere you control the <head>:

<link rel="stylesheet" href="/age/tokens/core.tokens.css">
<link rel="stylesheet" href="/age/design-system.css">
<script type="module" src="/age/design-system.esm.js"></script>

Optional — opt into dark mode by including the dark tokens and setting data-theme="dark" on <html>: 

<link rel="stylesheet" href="/age/tokens/core.dark.tokens.css">

From now on, <mud-button>, <mud-icon>, <mud-modal>, etc. work as native HTML tags.

3. Plain HTML / static site #

TL;DR Copy dist/design-system/ to public/age/ and reference it. Or use a CDN — but pin the version and add SRI. 

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>AGE demo</title>

    <link rel="stylesheet" href="/age/tokens/core.tokens.css">
    <link rel="stylesheet" href="/age/tokens/core.dark.tokens.css">
    <link rel="stylesheet" href="/age/design-system.css">
    <script type="module" src="/age/design-system.esm.js"></script>
  </head>
  <body>
    <mud-button variant="primary">Save</mud-button>
    <mud-icon name="check" size="md"></mud-icon>

    <mud-modal id="confirm" heading="Delete record?">
      <p slot="body">This action cannot be undone.</p>
      <mud-button slot="footer" variant="primary">Delete</mud-button>
    </mud-modal>
  </body>
</html>

CDN alternative [TBD]

The package declares "unpkg": "dist/mud/mud.esm.js", so any npm-mirroring CDN works once published.

!

Always pin a version and use Subresource Integrity (SRI). Without it, a CDN compromise silently runs attacker code on every page that loads the script. 

<link
  rel="stylesheet"
  href="https://unpkg.com/@egovmd/mud@0.0.1/dist/mud/tokens/core.tokens.css"
  integrity="sha384-REPLACE_WITH_REAL_HASH"
  crossorigin="anonymous">
<link
  rel="stylesheet"
  href="https://unpkg.com/@egovmd/mud@0.0.1/dist/mud/mud.css"
  integrity="sha384-REPLACE_WITH_REAL_HASH"
  crossorigin="anonymous">
<script
  type="module"
  src="https://unpkg.com/@egovmd/mud@0.0.1/dist/mud/mud.esm.js"
  integrity="sha384-REPLACE_WITH_REAL_HASH"
  crossorigin="anonymous"></script>

Generate hashes locally against the exact published files:

curl -sL https://unpkg.com/@egovmd/mud@0.0.1/dist/mud/mud.esm.js \
  | openssl dgst -sha384 -binary | openssl base64 -A
⚠

SRI caveat. SRI protects the entry file but cannot cover the lazy-loaded p-*.js chunks that design-system.esm.js imports dynamically — the browser has no integrity attribute on dynamic import().

If your threat model includes CDN compromise, self-host the build and apply SRI at your origin. CDN delivery is best for prototypes, internal tools, and demos.

4. PHP — Laravel, Symfony, WordPress, raw #

TL;DR PHP only emits HTML, so the integration is identical to plain HTML. Only the asset-URL helper differs per framework.

Laravel / Blade

{{-- resources/views/layouts/app.blade.php --}}
<head>
  <link rel="stylesheet" href="{{ asset('age/tokens/core.tokens.css') }}">
  <link rel="stylesheet" href="{{ asset('age/design-system.css') }}">
  <script type="module" src="{{ asset('age/design-system.esm.js') }}"></script>
</head>

<body>
  <mud-button variant="primary">{{ __('Save') }}</mud-button>
</body>

Place the build under public/age/ and the helper produces the right path.

Symfony / Twig

{# templates/base.html.twig #}
<link rel="stylesheet" href="{{ asset('age/tokens/core.tokens.css') }}">
<link rel="stylesheet" href="{{ asset('age/design-system.css') }}">
<script type="module" src="{{ asset('age/design-system.esm.js') }}"></script>

WordPress

Custom elements with hyphens are valid HTML5 — WordPress's wpautop and KSES filters will not strip the tags, but KSES will strip unknown attributes on some posts. Enqueue assets in your theme's functions.php: 

add_action('wp_enqueue_scripts', function () {
    wp_enqueue_style('age-tokens', get_template_directory_uri() . '/age/tokens/core.tokens.css', [], null);
    wp_enqueue_style('age-base',   get_template_directory_uri() . '/age/design-system.css',     [], null);
    wp_enqueue_script('age-loader', get_template_directory_uri() . '/age/design-system.esm.js', [], null, true);
});

// Make the loader a module — WP wraps scripts in classic <script> by default.
add_filter('script_loader_tag', function ($tag, $handle) {
    if ($handle === 'age-loader') {
        return str_replace('<script ', '<script type="module" ', $tag);
    }
    return $tag;
}, 10, 2);

Raw PHP

<link rel="stylesheet" href="/age/tokens/core.tokens.css">
<link rel="stylesheet" href="/age/design-system.css">
<script type="module" src="/age/design-system.esm.js"></script>

<mud-button variant="primary"><?= htmlspecialchars($label) ?></mud-button>

5. .NET — Razor, Blazor, MAUI, WPF/WinForms #

TL;DR Razor = same as PHP. Blazor works natively but needs JS interop for object props and a small [EventHandler] wrapper for custom events. WPF/WinForms require WebView2.

5a. ASP.NET MVC / Razor Pages

Identical to PHP. Drop the build under wwwroot/age/:

@* Views/Shared/_Layout.cshtml *@
<head>
  <link rel="stylesheet" href="~/age/tokens/core.tokens.css" />
  <link rel="stylesheet" href="~/age/design-system.css" />
  <script type="module" src="~/age/design-system.esm.js"></script>
</head>

<body>
  <mud-button variant="primary">@Localizer["Save"]</mud-button>
</body>

5b. Blazor Server / Blazor WebAssembly

Blazor (≥ .NET 7) renders custom elements natively. Attributes, slots, and @onclick work without ceremony: 

@* Pages/Demo.razor *@
<mud-button variant="primary" @onclick="HandleClick">
  Save
</mud-button>

<mud-modal heading="Confirm">
  <p slot="body">Are you sure?</p>
</mud-modal>

@code {
    void HandleClick() => Console.WriteLine("clicked");
}

Add the assets in App.razor (Server) or wwwroot/index.html (WASM):

<link rel="stylesheet" href="age/tokens/core.tokens.css" />
<link rel="stylesheet" href="age/design-system.css" />
<script type="module" src="age/design-system.esm.js"></script>

Three caveats:

  1. Object/array props must be set via JS interop — see §6.
  2. Custom events (corChange, corSelect, …) need an [EventHandler] registration — see §7.
  3. Render mode: in interactive Server mode, SSR emits tags before design-system.esm.js runs. That is fine (custom elements upgrade automatically), but JS interop that sets a property must wait for upgrade: 
    await JS.InvokeVoidAsync(
    "eval",
    """
    customElements.whenDefined('mud-select').then(() => {
      document.getElementById('mySelect').options = ...;
    });
    """);

5c. MAUI Blazor Hybrid

Same as Blazor WebAssembly. Assets ship inside wwwroot/ and are served by the embedded WebView2 (Windows) or WKWebView (macOS / iOS).

5d. WPF / WinForms (desktop)

Custom elements only work in a WebView2 control — there is no native HTML rendering in Win32. Embed a local HTML page exactly as in §3 and load it: 

await webView.EnsureCoreWebView2Async();
webView.CoreWebView2.SetVirtualHostNameToFolderMapping(
    "app.local", "Resources/age", CoreWebView2HostResourceAccessKind.Allow);
webView.Source = new Uri("https://app.local/index.html");

6. Setting non-string props (objects, arrays) #

TL;DR Attributes are strings. For object/array data — mud-select.options, mud-breadcrumb.items, mud-receipt.lineItems — wait for customElements.whenDefined and assign the JS property.

HTML attributes are strings. Several AGE components accept structured data via JS properties instead:

  • <mud-select> → .options = [{ label, value }, …]
  • <mud-breadcrumb> → .items = [{ label, href }, …]
  • <mud-receipt> → .lineItems = [...]

For these, the attribute form (options='[…]') does not work. Wait for upgrade, then assign: 

<mud-select id="country"></mud-select>

<script type="module">
  customElements.whenDefined('mud-select').then(() => {
    const el = document.getElementById('country');
    el.options = [
      { label: 'Romania', value: 'RO' },
      { label: 'Moldova', value: 'MD' },
    ];
  });
</script>

Blazor equivalent

@inject IJSRuntime JS

<mud-select @ref="selectRef"></mud-select>

@code {
    ElementReference selectRef;

    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        if (!firstRender) return;
        await JS.InvokeVoidAsync("setCorProp", selectRef, "options", new[] {
            new { label = "Romania", value = "RO" },
            new { label = "Moldova", value = "MD" },
        });
    }
}

Ship the helper once:

// wwwroot/age-interop.js
window.setCorProp = async (el, prop, value) => {
  await customElements.whenDefined(el.tagName.toLowerCase());
  el[prop] = value;
};

7. Listening to custom events #

TL;DR DOM addEventListener always works. For Razor @oncorclose syntax, register an [EventHandler] in a tiny helper assembly.

AGE components dispatch namespaced events (corChange, corSelect, corClose, …). DOM listeners work everywhere: 

<mud-modal id="m"></mud-modal>
<script type="module">
  document.getElementById('m').addEventListener('corClose', e => {
    console.log('closed', e.detail);
  });
</script>

Blazor — enable @oncorclose syntax

Create a small assembly:

[EventHandler("oncorclose", typeof(EventArgs), enableStopPropagation: true, enablePreventDefault: true)]
public static class CorEventHandlers { }

Reference it from _Imports.razor:

@using YourApp.JsInterop

Then:

<mud-modal @oncorclose="HandleClose"></mud-modal>

Alternative without [EventHandler]: attach the listener manually in OnAfterRenderAsync via JSInterop and forward to a DotNetObjectReference.

8. Dark mode #

TL;DR Include core.dark.tokens.css and set data-theme="dark" on any element. The dark overrides are scoped to that subtree.

The dark stylesheet scopes its overrides to [data-theme='dark']. To switch modes, toggle the attribute on <html>: 

document.documentElement.dataset.theme = 'dark'; // or 'light'

Pattern with prefers-color-scheme fallback + persistence:

const stored = localStorage.getItem('theme');
const dark = stored
  ? stored === 'dark'
  : matchMedia('(prefers-color-scheme: dark)').matches;
document.documentElement.dataset.theme = dark ? 'dark' : 'light';
i

You can also scope dark mode to a subtree — apply data-theme="dark" to any wrapping element and only its descendants flip.

9. Hosting & cache strategy #

TL;DR Self-host in production, fingerprint chunks (long cache), short-cache the entry, gzip everything, configure CSP with setNonce().

  • Same-origin or CORS. ESM imports honor CORS. Third-party hosts must send Access-Control-Allow-Origin. unpkg and jsDelivr already do.
  • Subresource Integrity (SRI). Any third-party-hosted asset must carry integrity="sha384-…" + crossorigin="anonymous". SRI only covers files referenced directly in markup; lazy-loaded chunks cannot be SRI-protected because they are pulled via dynamic import(). Self-hosting eliminates this gap entirely — prefer it for production.
  • MIME type. .js must be served as application/javascript (or text/javascript). Legacy servers that default to application/octet-stream will cause the browser to refuse the module.
  • Cache headers. Chunks (p-*.js) are content-hashed and safe to serve with Cache-Control: public, max-age=31536000, immutable. The entry design-system.esm.js is not hashed — give it a short cache (e.g. 5 min) or version it via your asset pipeline.
  • Compression. Enable Brotli / gzip on .js, .css, .svg.
  • CSP. The loader uses dynamic import(). Production is CSP-friendly with script-src 'self' + a nonce. Call setNonce(…) before the loader runs: 
    <script type="module" nonce="abc123">
  import { setNonce } from '/age/loader/index.js';
  setNonce('abc123');
</script>

10. Troubleshooting #

TL;DR Most failures trace to a split deploy (chunks 404) or token CSS loaded after component CSS. Both are visible in DevTools → Network.

Symptom Likely cause Fix
<mud-button> renders as plain text, no styling The loader didn't run, or chunks 404 DevTools → Network. If design-system.esm.js is 200 but p-*.js chunks are 404, the folder is split — re-deploy dist/design-system/ as a whole.
Icons render as blank squares Asset resolution failed The SVG sprite path is derived from design-system.esm.js's URL. Ensure dist/mud/assets/ is co-located with the entry.
Modal/popover positioned wrong Tokens not loaded Verify core.tokens.css is in the document before design-system.css. Otherwise component CSS resolves variables to fallback.
Dark mode doesn't apply Missing dark tokens or wrong attribute Confirm core.dark.tokens.css is linked and <html data-theme="dark"> is set.
Blazor: e.target.value is empty in event handler Stencil emits typed CustomEvent; value lives on event.detail Use e.Detail (Blazor) or e.detail (JS).
<mud-select> shows no options after data load Tried to set options as an attribute Set the JS property after customElements.whenDefined(). See §6.
Console warns about dev mode You shipped the dev build (stencil build --dev) Run yarn build and deploy the dist/ from that run.
CSP blocks the loader script-src doesn't allow dynamic imports / no nonce Add a nonce, call setNonce(), or relax to 'self' for module sources.
