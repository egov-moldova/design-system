# @egov-moldova/mud-react

React adapter for the AGE Design System. Provides strongly-typed React wrappers
around every Stencil-compiled `cor-*` custom element so consumers get JSX-friendly
props, refs, and event handlers (`onCorChange` instead of `addEventListener`).

The wrappers are generated by [`@stencil/react-output-target`](https://www.npmjs.com/package/@stencil/react-output-target)
from the AGE Stencil build (`yarn build` at the repo root). They live in
`src/components/stencil-generated/` and are re-exported from `src/index.ts`.

## Install (published)

```bash
yarn add @egov-moldova/mud-react @egov-moldova/mud react react-dom
```

## Usage

```tsx
import {
  defineCustomElements,
  CorButton,
} from '@egov-moldova/mud-react';

// Token + global stylesheets from the underlying @egov-moldova/mud package.
// styles.css also loads the Onest font; no @font-face of your own is needed.
import '@egov-moldova/mud/tokens/core.tokens.css';
import '@egov-moldova/mud/styles.css';

// Register the custom elements once at app startup.
defineCustomElements();

export function App() {
  return (
    <CorButton variant="primary" onCorClick={() => console.log('clicked')}>
      Click me
    </CorButton>
  );
}
```

`defineCustomElements()` is idempotent — calling it more than once is a no-op.

## Local development against SIMSM (link workflow)

`@egov-moldova/mud-react` is not yet published. During development, the SIMSM
monorepo (`/Users/mdascal/Projects/corlab/amdm/`) consumes it via a global
symlink.

### 1. Build the React adapter in the AGE repo

```bash
cd /Users/mdascal/Projects/corlab/age/age-design
yarn install                # first time only
yarn build.react            # depends on `yarn build` (which generates the proxies), then runs `tsc` in packages/react/
```

Every non-dev `yarn build` runs the React output target, which empties and regenerates
`packages/react/src/components/stencil-generated/`. `yarn build.react` depends on that
build (no second Stencil run, cached when nothing changed) and then invokes `tsc` inside
the `packages/react/` workspace to produce `packages/react/dist/`.

### 2. Register the global link

`yarn link` in Yarn 4 is project-scoped; for cross-repo symlinks the AGE team
uses `npm link` (it just creates a node_modules symlink — package manager
neutral on the consumer side):

```bash
cd /Users/mdascal/Projects/corlab/age/age-design/packages/react
npm link                    # registers @egov-moldova/mud-react globally
```

### 3. Consume the link in SIMSM

```bash
cd /Users/mdascal/Projects/corlab/amdm/apps/frontoffice
npm link @egov-moldova/mud-react
```

SIMSM now resolves `@egov-moldova/mud-react` to your local `packages/react/dist/`.

### Watch loop during development

The Stencil watch (`yarn dev` at the AGE root) rebuilds the custom elements,
but it does NOT regenerate the React proxies — the output target runs only in
non-dev builds (`yarn build`, not `--dev`). After changing a `cor-*` component's public API (props / events /
methods), re-run:

```bash
yarn build.react
```

The SIMSM dev server will pick up the new `packages/react/dist/` on its next HMR cycle.

### Unlinking

```bash
# In SIMSM
cd /Users/mdascal/Projects/corlab/amdm/apps/frontoffice
npm unlink @egov-moldova/mud-react

# In AGE
cd /Users/mdascal/Projects/corlab/age/age-design/react
npm unlink
```

## API

- `defineCustomElements(opts?)` — registers every `cor-*` custom element on the
  current document. Idempotent. Returns `Promise<void>`.
- `setNonce(nonce)` — applies a CSP nonce to Stencil's injected `<style>` tags.
- `Cor<Name>` — one React component per Stencil component (e.g. `CorButton`,
  `CorInput`, `CorSelect`).

TypeScript users get full prop typing forwarded from `@egov-moldova/mud`'s
generated `components.d.ts`.
